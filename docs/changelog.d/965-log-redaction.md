- **Redacted meeting diagnostics (TC-965).** INFO logs use counts, lengths, durations, per-meeting speaker indices, and short hashes of internal meeting IDs instead of participant names, transcript/caption text, meeting URLs/native codes, signed URLs, tokens, SQL parameters, object keys, or exception bodies. Meeting API, gateway, rollback CLI, and admin API entrypoints configure handler-based JSON sanitizers before app construction; Uvicorn access logs are disabled. Python warnings, process/thread/unraisable exceptions, and bot/remote-browser fatal events use sanitized boundaries; fastapi-guard handlers are removed and its request/suspicious logging is disabled. SQLAlchemy engines hide bound parameters and echo logging is disabled. AWS sync output is discarded rather than buffered. A dynamic CI inventory scans package bins/scripts, Dockerfile commands, compose commands, and Python main entrypoints; every launch target is covered or explicitly excluded. `DEBUG_ADMISSION` is explicit opt-in, count/locale-only, and unset in deployed ptx compose.
